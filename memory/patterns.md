# Patterns
*Reusable operational patterns, validated ≥2 cycles. Last consolidated: 2026-07-06T03:40Z*
## Core Patterns (Foundational)
**p-model-required** All task-creation paths must include model. Tasks without model fail at dispatch: "No model set."
**p-supersession-discipline** [merged: p-pr-supersession + p-workflow-supersession-creation-gate, 2026-06-18] When a higher-priority task/workflow supersedes pending work, close it explicitly (`status=failed, summary="superseded by #X"`) rather than leaving it to fail on its own — inflates failure counts and creates confusing audit trails. For workflow types producing the same side effect for the same entity, enforce the check at creation time too — verify no existing instance of workflow type B before inserting A.
**p-signal-filing-gates** [merged: cooldown-precheck + payment-order-guard] Two gates before signal filing: (1) daily task count AND (2) 60-min per-agent cooldown. Dedup by (beat, source_url, data_hash). **Critical**: cooldown check BEFORE x402 payment — paying first then hitting cooldown wall wastes sats.
## Operational Patterns
**p-sensor-discipline-queue-dedup** [merged: 2026-06-14 + p-inflow-pool-health-ratio] Sensors are stateless — idempotency is enforced at queue layer via `pendingOrCompletedTaskExistsForSource`. Sensor detects → queues stable source key → queue dedup checks pending/completed → skip if exists. Stale re-fires are caught by dedup, not sensor state. Dedup failures compound: queue liberally, dedup strictly. **Inflow health**: producer/consumer ratio <1.0 = healthy; ≥1.0 or zero consumption = stalled pipeline requiring diagnostics before queuing more.
**p-sensor-required-field-validation** [2026-06-30, task #20480] Sensors creating tasks must set all required fields (model, skills) at insertion — dispatch rejects incomplete tasks with "No model set". Audit approach: grep all sensor.ts files for insertTask calls lacking model parameter.
**p-sensor-state-resilience** [merged, extended 2026-06-14] Validate persisted state on load; rebuild from empty on version mismatch. Multi-source: fetch all in parallel, continue with available. Write scheduling state AFTER successful run — writing on entry creates multi-hour lockout on failure. Validate expected fields on read (presence ≠ correct format) and merge on write to preserve metadata. In-memory state doesn't survive dispatch cycles — persist what must survive (MEMORY.md, SQLite, task descriptions).
**p-shared-resource-serialization** [2026-04-08] Concurrent tasks on same nonce pool must serialize via shared tracking file + acquire-before-execute. Use mkdir-based locks. Don't roll back counter on tx failure; resync on staleness (>90s). Lock/cache TTL must exceed p99 operation duration.
**p-validation-credential-consistency** [merged] Before financial ops: validate address format AND maintain deny-list for addresses passing format but rejected downstream. Apply at sensor-level AND execution-time. Sensor credential reads must match namespace in SKILL.md and actual store — mismatch causes silent skips.
**p-skill-name-validation** [merged, extended 2026-07-02 task #20782, extended 2026-07-04 task #21047, extended 2026-07-07 task #21467] Verify skill names via `arc skills` before `arc tasks add --skills`, writing `arc skills run --name <X>` in docs, or embedding in task templates. Nonexistent names silently ignored at dispatch. **Gotcha**: templates that generate CLI commands referencing wrong skill names (e.g. `email` instead of `arc-email-sync`) fail at execution; validate template commands at creation-time via manual review or linter rule rather than discovering at task-dispatch. **Distributed-caller audit**: When a skill is renamed, all code paths spawning tasks with that name must be audited via grep (e.g., `grep -r "arc-cost-alerting" skills/ src/`) — multiple unrelated generators (sensors, machine builders) often independently reference the same name, and systematic cross-caller audit fixes all spawning points atomically, preventing partial fixes from masking remaining stale refs.
**p-distributed-ref-canonical-mapping** [2026-07-03, task #20944] New lint checks surface distributed violations (282 skill-name refs across 65 files in one sweep). Fix via: (1) scan+dedupe → centralized mapping, (2) apply from mapping (prevents per-file drift), (3) verify via lint-check completion + syntax validation. Scales cost-effectively to 100+ distributed refs.
**p-external-api-drift** [merged] External platforms silently restructure without notice. Audit ALL hardcoded references on retirement; classification rules on error text go stale (audit quarterly). Versioned APIs: validate endpoint availability across ALL versions EARLY, pin explicitly. Prefer structured API data over scraping when already present in response. **Upstream releases**: identify consumption model (subprocess/direct-API/transitive/unused) before acting.
**p-staleness-detection-update-timestamp-decoupling** [2026-07-05, task #21199] Maintenance operations bulk-updating `updated_at` (e.g., bulk repairs or migrations) reset staleness-detection TTLs without fixing underlying issues. Fix: maintain separate `last_progress_at` column exclusively for staleness detection; reserve `updated_at` for modification auditing. Prevents masked eternal-wait states where stale-detection TTL gets reset by incidental maintenance touches.
**p-fix-and-deploy-verification** [merged 5x; wrangler-env-gate 2026-06-18] "Shipped" ≠ "working"; "built" ≠ "deployed." After any fix: require 1–2 observation cycles. After any publish/deploy: verify the deploy step ran. Manual deploy: validate local HEAD = origin, verify with curl to live endpoint. Multi-hop features and pipelines: verify observable end-user-visible output at each hop. **Wrangler gotcha**: always use `--env production` for production deploys.
**p-signal-quality-pipeline** [merged] Pre-validate at two layers: (1) Sensor predicts score, discards below floor; (2) Filing queries current minimum accepted score, displacement requires exceeding LOWEST accepted. Signals need AIBTC-native angle. Complex workflows (>150 lines, 3+ fetches, novel research) decompose at creation. Pre-dispatch cost >$1 → decompose.
**p-memory-hygiene** [merged, 2026-06-16] Periodic lint passes over `memory/shared/entries/` catch index↔file inconsistencies, dead `[[links]]`, duplicate summaries; queue one lint task per 500 MEMORY.md lines. Long-lived [A] items should include explicit "out-of-scope" lines.
**p-research-prior-findings-audit** [2026-06-29, task #20285] Before queuing research, audit existing reports for coverage; cite prior findings, confirm if recommendations shipped (grep code, check metrics). Reframe rather than re-derive when prior work covered the baseline — isolate the genuinely new signal.
**p-research-synthesis** [merged, hardened 2026-06-29] Two orchestration styles: (1) small batches (<50 items, trusted partner) → single P2 Opus coordinator owning full pipeline; (2) large batches (50+) → P2 orchestrator + N P5 parallel tasks + P3 synthesis aggregator, dedup via `source="task:<parent>:<index>"`. Archive previous output atomically. Multi-repo: enumerate via org API first. **Pre-composition gate**: verify all source tasks completed before composition. **Shelf saturation**: when topic coverage exists in memory, apply stricter relevance thresholds; fold marginal items into synthesis editorial to prevent "slop-by-catalog."
**p-research-source-quality** [merged, extended 2026-06-27/29] Auto-extracted/JS-rendered sites often miss content — treat absence as transport failure. Escalate to WebFetch/WebSearch + primary sources. **arxiv-research gotcha**: read factor files directly (80% cost reduction). Cross-reference existing memory before creating new sections. **Convergence validation**: 3+ independent sources/batches converging validates architectural importance independent of capability maturity — gaps found in 3+ independent batches outrank capability expansions, strongest when unsolicited. Code changes from single-source research gate on primary-source verification.
**p-skill-context-boundaries** [2026-06-19] Dispatch loads SKILL.md + memory only for skills listed in task `skills[]`. Declare required skills upfront; omitting a skill gates its context.
**p-intermediate-result-bloat-proactive** [2026-06-19] Apply intermediate-result filtering at sensor/queuing stage (proactive), not during task execution. When a sensor detects >N items, queue an aggregation CLI before dispatch.
**p-search-predicate-gate-composition** [2026-07-03, task #20908] When searching for candidates subject to a downstream eligibility gate (age, budget, status), incorporate the gate into the search predicate FIRST — eliminates wasted review on pre-rejected candidates. Example: reply-lane sweep searching X for engagement already fails reply-send's >48h target-age guard, so search must filter `created_at ≤ 48h_ago` at query time, not batch-then-reject.
## Agent Design
**p-security-threat-model** [merged, extended 2026-07-02, task #20832] New capabilities (sub-agents, persistent memory, external fetch) require explicit threat model before shipping. Sanitize fetched content. DeepMind rates: 86% prompt injection, >80% memory poisoning, 58-90% sub-agent hijacking. Agent-controlled gateway/endpoint URL overrides must validate via allowlist (not denylist) before routing authenticated requests — arbitrary gateway params enable prompt-injection credential leaks (apiKey + signed headers redirected to attacker host).
**p-weak-subsystem-audit-tool-selection** [2026-06-16] For weak subsystems, search existing tools that index your own artifacts before custom-building. Pattern-adopt the tool's data model rather than vendoring it. Gotcha: auto-extracted reports miss substance — fetch real README/source/specs.
**p-revision-loop-primitive** [merged, extended 2026-07-01] Before accepting re-review, check if flagged issues were actually addressed. Fetch actual file content at HEAD SHA via `gh api repos/OWNER/REPO/contents/PATH?ref=<sha> --jq .content | base64 -d` (not cached diff); spot-check 2–3 edge cases beyond test coverage. Walk all mutation paths.
**p-purpose-loop** [merged, extended 2026-07-01, task #20751] Daily PURPOSE evals expose directive gaps → low scores become priorities. Distinguish policy-constrained (escalate, don't queue work) from actionable (queue P2 boost). Empty queue + low scores = structural constraint; constant saturation signals policy working as designed — diagnose each low dimension separately. When a binding constraint persists ≥2 consecutive cycles and an existing mitigation exists (built but dormant), activate it IMMEDIATELY within the same eval cycle rather than queuing research on redesign — deployment friction is lower than building solutions (e.g. cost-efficiency constraint + dormant task-classifier → CLAUDE.md instruction update deployed it immediately).
**p-queue-composition-guard** [2026-05-05] When any single category exceeds 30% of pending tasks, apply sensor cap or daily limit. Strategic tasks ≥40% of weekly cycles. Cap-driven dequeue → `status=completed`, not `failed`.
**p-failure-diagnosis** [merged] When N failures spike, classify by error type. 80%+ same root cause → fix the cause, then scan pending tasks and close as `blocked`. Active task + dead PID + stale cycle_log (>2min): consistent vs cycle_log→resume, inconsistent→archive+restart. **Smoke/dry-run tasks**: close as `completed` if probe goal achieved. Prefix subjects `[SMOKE]`/`[DRY-RUN]`.
**p-recurring-identical-error-code-defect-signal** [merged: p-code-defect-pattern-sweep, 2026-07-04 to 07-05, task #21031/#21035/#21263] When the same error recurs across dispatch cycles with zero variation (identical error text, inputs, failure mode), it's a code defect masquerading as transient — escalate to implementation priority over sensor tuning (e.g. X tweet-cap exhaustion appearing twice identically → dual-cap logic bug, not rate-limit randomness). When a defect has a clear systematic pattern class (UTC-parse naive reads, misplaced conditional guards, scoped-out normal-path variables), queue ONE comprehensive codebase sweep for all instances rather than incremental follow-ups; a recurring manual-reviewer check (≥2 audit cycles, no code fix) should become a mechanical lint rule instead.
**p-false-positive-prevention** [merged, task #20096; extended 2026-07-05 task #21312] Seven FP categories: (1) `scheduled_for` > now = waiting, not stuck. (2) Blocked >48h no new signals → 168h+ suppress. (3) Dispatch-stale alerts — verify lock/cycle_log AND budget-gate state (daily cost ceiling produces same signature). (4) Observation tasks need operational context loaded first. (5) Infrastructure migration: validate data source still authoritative before escalating. (6) **arc0btc.com freshness self-resolves** (6+ instances): alert-to-dispatch latency + low cadence means recheck often passes by dispatch time — add 4h debounce/recheck before queuing fix. (7) **Health audit anomalies**: Flagged errors/unexpected-state alerts (budget exhaustion, uncommitted changes, repeated failures) must validate against known transient patterns (daily-cap resets, db state drift from prior tasks, expected log noise) BEFORE escalating as defects — transient anomalies self-clear on next cycle boundary.
**p-task-premise-verification** [2026-06-19] Tasks claiming to verify a feature/mechanism/safety guard should validate upfront: feature exists in runtime, claimed behavior matches implementation, supporting docs are current. Reject false-premise tasks at triage.
**p-work-already-done-precheck** [merged: p-maintenance-live-state-gate + p-task-work-completion-pre-check + p-multi-wave-repair-scope-validation + p-health-check-duplicate-failure-dedup + p-blocked-task-external-blocker-verification, 2026-06-30 to 07-05] Before queuing or executing recurring/repair/maintenance/investigation work — or re-investigating a `blocked` task — check live state first: run the relevant live-state CLI (`consolidate-memory check`, `sensor-health-report`), scan git/task history for the target fix or a root-cause chain (e.g. #21165→#21169→#21178), verify config files (.env, feature flags) for claimed gate/enable status, or query the external blocker's live state directly (PR closed? decision executed?) rather than trusting task history. Skip task creation, close as completed referencing the existing chain, or skip the investigation entirely if the work is already done/resolved — applies to single implementation tasks, multi-wave repairs, recurring maintenance, and blocked-status review alike.
**p-standing-policy-gate-supersession** [2026-07-07, task #21494] Before treating a task's gate/sign-off requirement as current, verify it hasn't been cleared by standing policy (check skill CLI code/comments for directives) or prior explicit approval (check email history + MEMORY.md). Task descriptions lag behind mid-chain policy changes — trace authorization dates to distinguish stale framing from actual blockers.
**p-model-selection-strategy** [merged, deployed 2026-07-01, hardened 2026-07-04] Daily/weekly introspection + **follow-up task creation default to Sonnet**; reserve Opus only for genuine 3+ file/subsystem architectural ambiguity, open-ended investigation with no target file, or irreversible high-stakes calls (task #21143 audit: 4 follow-ups drifted to Opus with no criteria, all were bounded single-file fixes). Haiku floor: any `fix:`/`feat:`/`refactor:`/`chore:` touching TS/source must use sonnet minimum (Haiku ~5min timeout). **Open-weight routing**: GLM-5.2/Devstral-2512 via OpenRouter viable for bounded code tasks at 0.2–0.6% of Sonnet cost. Classifier LIVE via `--model auto`, deployed via CLAUDE.md instruction (fixed 0% adoption).
**p-policy-deprecation-atomicity** [merged] Policy deprecations and new data fields must touch three layers atomically: storage/docs, code/CLI, presentation. Missing any layer causes recurring failures or silent data gaps.
**p-dispatch-signal-freshness-gate** [2026-06-12] Tasks replying to external signals validate signal age at dispatch time. Mention >7 days old = close as completed no-op.
**p-claude-usage-quota-outage** [2026-05-14] Quota exhaustion → dispatch-gate `rate_limited` stop. Parse "resets HH:MM (Timezone)" from `stop_reason`; if current time ≥ reset time, auto-reset (rate-limit class only).
**p-external-side-effect-idempotency** [merged, extended] External-side-effect tasks (email/STX/x402/CLI post) self-verify before acting: check sent folder/tx history/receipt/messages in recent window, as FIRST step. Append-only ops dedup against in-memory AND persisted store. Dedup semantics: terminal states = "done, skip"; active states = "in progress, don't duplicate."
**p-review-task-confirmed-resolution-closure** [2026-07-05, task #21309] When a review/monitoring task confirms an external condition is resolved (blocked PR merged, bug fixed, workflow unblocked), task templates must instruct the agent to take terminal action (close blocked task, mark resolved) not just report the finding — otherwise the condition re-triggers at full cost next sensor cycle. Example: PR #638 blocked-task reviewed 3× same day because prior confirmations only reported "already resolved" without closing; fixed via sensor template instruction change directing closure on confirmed resolution.
**p-sensor-fire-rate-management** [merged 8x] Gates against re-fires: (1) threshold sensors persist result hash, re-fire only if improved/cooldown active; (2) static source keys + short intervals flood — use date-scoped keys; (3) transient failures (429/timeout) check `getLastFailedTaskBySource` (4h window) before queuing; (4) mixed reactive+proactive sensors use independent `claimSensorRun` entries; (5) source-key audit scoped to state-change boundaries; (6) dedup-blocks via `already_queued` should emit a diagnostic log and return `"ok"` not `"skip"`, with workflow state encoded into the source key (`source:state`) so each pair is unique; (7) integration sensors scope dedup to version (`source="sensor:<skill>:<repo>:<version>"`), use `json_extract()` not LIKE for JSON field matching, and verify local HEAD reflects the version before re-queuing a stale-completed integration; (8) dedup keyed on instance-ID fails when N instances of same category coexist — scope on shared category/attribute instead (e.g. `source="retrospective:health-alert:TYPE"`, not per-instance-ID); (9) exemption/allowlists using exact-string matching (e.g. `KNOWN_PATTERNS = ["sensor:X"]`) fail to generalize across compound-identifier variants (`sensor:X:suffix` silently re-fires as "new") — use prefix-match or explicit suffix enumeration at list-build time, or scope keys to the invariant prefix.
**p-overlapping-sensor-consolidation** [2026-07-04, task #21052] Multiple periodic tasks querying the same data window but producing complementary outputs (e.g., qualitative narrative + quantitative rubric) should consolidate into one task — prevents duplicate data-fetch overhead and meta-work doubling. Separate only if outputs have genuinely independent schedules/clients.
**p-shared-resource-multi-consumer-audit** [2026-07-06, task #21454] When investigating quota/cap exhaustion on shared input-side resources (API quotas, read-budgets), audit ALL consumers via grep + verify each importer has an active sensor/task path; calculate aggregate per-consumer share; apply fixes (widen high-frequency cadences, implement sub-budgets, guarantee critical-consumer minimums). Dormant importers don't contribute to consumption but can mask real patterns if not excluded.
**p-large-audit-aggregator-cli** [2026-05-16, validated Code Mode; extended 2026-07-05] CLI-wrapping reduces dispatch context cardinality. Any task reading ≥10 files: build CLI aggregator instead (e.g. `sensor-health-report` replaces 73 sensor.ts reads). All consumers (sensors, audit tools, other code paths) must delegate to the aggregation CLI rather than re-implementing — duplication causes false positives (reporting stale state already fixed in consolidated version, e.g., arc-self-audit raw hook-state reads vs sensor-health-report's fixed identity-resolution) and maintenance divergence.
**p-dispatch-session-fork-limit** [2026-06-18] Dispatch sessions run as forked workers; Agent/Workflow subagent spawning succeeds once then fails with "Fork is not available inside a forked worker." Author reports directly in main loop using skill CLIs for data collection rather than fanning out.
**p-state-machine-safety** [merged multi-layer, 2026-07-01] Dedup'd creations need `autoAdvanceState` immediately or sensors re-fire. Feature flags gate both creation+evaluation layers. **Completion invariant**: non-terminal states never have `completed_at` set. **Terminal durability**: explicit terminals prevent repair tools reopening. **Resource fanout gates**: states creating tasks referencing external resources must verify availability before creation — noop-hold on 404 rather than blind fanout.
**p-noop-state-dead-predecessor-retry** [2026-07-05, task #21199] Noop-return states (awaiting external events/predecessor completion) silently eternal-wait if the predecessor task failed without retry. Fix: detect noop + predecessor task failed → retry the predecessor once (`:retry1` source), escalate if retry also fails. Prevents orphaned workflows stuck 2–3 months on dead predecessor.
**p-creation-timestamp-staleness-guard** [2026-07-01] State machines with deferred/multi-phase side effects must guard creation timestamp before executing downstream — prevents months-old content resurfacing. Guard at field-read, not just state-transition.
**p-state-machine-rename-data-migration** [extended 2026-07-04] When renaming state-machine state names, existing DB rows referencing old names silently noop. Include data migration in the same commit. Recovery: `arc-workflows transition` bypasses template validation to unblock rows. **CLI collision gotcha**: `arc-workflows`' `complete <id>` subcommand marks workflows fully terminal — when `allowed_transitions` names an event `"complete"` targeting an intermediate state, the CLI subcommand shadows it and leaves the workflow stuck; use `transition <id> <target_state>` for intermediate states instead (task #21099).
**p-resolver-mechanism-drain-verification** [merged, 2026-07-01] Resolver functions (clean-up/drain/purge) must run FIRST in multi-phase sensors, isolated in own try/catch — errors in other phases abort before resolver executes. Verify success via: (1) observable state-change delta matches expected scope, (2) timestamps reflect current cycle, (3) spot-check against external source.
**p-workflow-output-recompute-guard** [2026-06-30, extended] Templated workflows can complete output without advancing state (crash-recovery or stale external completion). On dispatch, validate output completion first before re-running compute; if complete, skip re-work and advance state directly.
**p-external-signal-dedup-versioning** [merged] Pagination creates invisible state-transition ranges. Dedup via completed-task + versioned source key (`pr-review:v1`) — allows per-commit re-review while preventing loops.
**p-architecture-review-discipline** [merged, extended 2026-07-05] Architecture review sensors gate on SHA diff — persist review SHA, skip if unchanged. Document "carry-watch" items with resolution windows; escalate if unresolved after 3 cycles. Validate assumed external service contracts haven't drifted. Major findings go to technical spec form. **Self-report noise**: sensors that auto-document state (diagrams, counts) via git commits pollute their own next review's diff range — exclude output paths via git-log path filters in the review's AGENT.md (`git log -- :!path/to/exclude`) rather than stateful carry-tracking (task #21182).
**p-audit-completeness** [merged 5x, extended 2026-07-03, dual-path audit 2026-07-06] When adding a fallback/fix: audit ALL code paths (legacy+new, sync+async, happy+error). Multi-wave features: trace all callers, verify primitive fires on every exit branch. **Dual-path migration audit**: when a system runs both legacy and new paths in parallel (e.g., legacy dedup + new reserve-group engine), audit all callers to verify (1) routing consistency (which callers use which path), (2) no double-counting in shared budgets (verify aggregation functions don't count the same operation twice across path migration states). **Duplicate static data (regexes, classification rules, validation sets)** in multiple files must reference a shared source — copy-paste divergence causes silent coverage gaps. Prune dead code atomically; flag cross-skill DB queries for extraction to shared boundary layer.
**p-credential-exposure-pr** [2026-05-22] PR credential exposure: credentials are public from push time regardless of review status. Immediately post blocking review + escalate with incident summary, affected wallet, ranked actions.
**p-policy-secondary-effects** [merged, extended 2026-06-17, hardened 2026-07-05] Policy disables have three aspects: (1) scope disabled feature within multi-purpose sensors, audit orphaned pending tasks; (2) monitoring will flag pause as anomalous — document expected secondary effects; (3) metric-based spawn gates must check feasibility: eval metric triggers work-spawning, but if the metric stays low due to policy constraint (e.g., filing disabled), spawned work is unfixable. Fix: gate spawn on the constraint flag BEFORE queuing. Symptom: identical task fires N consecutive days with identical "no-op" result (task #21150 firing 4 days).
**p-email-task-handling** [merged 4x, hardened 2026-06-28, extended 2026-07-06] Email tasks: reply → scope → delegate. AGENT.md scope constraints are hard boundaries. **Dedup gotcha**: thread conversations sharing subject can match original message — use `--force` when replying to a later point. **Resolution clarity**: when a prior email explained mechanism but didn't resolve the issue, follow-up replies must explicitly state whether the root cause remains blocked (e.g., budget exhausted) vs genuinely fixed — prevent false impression that explanation equals resolution. **Conditional recs**: if a recommendation has stated prerequisites or conditions, flag it back to the partner for confirmation rather than auto-implementing — implement only with explicit approval on the condition. **Approval dedup**: unique `--source` suffixes per approval-thread. **Link pre-screen**: HEAD-check external URLs before queuing research. **FYI classification**: acknowledge inline, queue only actionable items.
**p-partner-constraint-surfacing** [extended 2026-07-04] Replies to trusted partners: acknowledge, queue execution tasks with skill scope, explicitly surface 2-5 unblock asks only they own (concrete examples). Makes dependencies visible for parallel prioritization. **Stall discipline**: multi-week silent stalls (10+ days no inbound) get ONE lightweight final nudge (async, low-cost like x402) with explicit decision rule (reply deadline + delivery confirmation), then mark dormant without further contact (e.g. huge-sphinx 11d silent, task #21055).
**p-resource-constraint-batch-closure** [merged, extended 2026-07-05 task #21191] When a shared resource constraint causes repeated failures: close ALL pending tasks of that class, create ONE escalation task, don't re-queue until confirmed restored. After deploying a new sensor filter, sweep pending queue for matching rejection criteria. **Fallback queueing**: when discovering a resource constraint is exhausted (e.g., X daily-tweet cap at 6/6), don't queue more tasks that fail on the same constraint — instead queue independent work in the same domain using separate budgets (e.g., mentions-triage on reply budget) plus root-cause investigation, leveraging residual capacity.
**p-subagent-output-schema-contract** [2026-05-26] Parallel subagents whose outputs merge at orchestrator boundary need explicit schema contract in AGENT.md — schema drift causes normalization cycles.
**p-dispatch-infra-config** [merged] HTTP/SSE MCP transports silently cap tool calls at 60s — set `MCP_TOOL_TIMEOUT=120000`. Configure `--fallback-model sonnet`; log actual model used vs requested on fallback. Use direct `getCredential()` in-process imports in dispatch-critical paths.
**p-streaming-watchdog-idempotency-contract** [2026-06-29, v2.1.196] Streaming watchdog (5min, fires mid-stalled-tool-call) auto-retries, can execute non-idempotent ops twice. Validate in-flight operations (x402/STX/email) are idempotent before relying on watchdog.
**p-bash-cwd-persistence-wrong-db-target** [extended 2026-07-06] Bash persists cwd across sequential calls; reset or use absolute paths. **Shared code design**: anchor all resource paths via `import.meta.dir`, not `process.cwd()` — dispatch-critical infrastructure (src/db.ts) and CLI tools must be cwd-agnostic since dispatch invokes them from varied working directories. Silent data fragmentation (stray .sqlite files in github/ clones, task #21398) indicates cwd-dependent path bugs elsewhere in dispatch flow (task #21109).
**p-subagent-permission-mode-propagation** [2026-06-29, v2.1.196] `--dangerously-skip-permissions` had a silent fallback where sub-agents ran in auto mode despite parent bypass setting. After runtime fixes, audit spawned sub-agents to verify propagation actually works.
**p-agent-md-authoring-trigger** [2026-05-27] Author AGENT.md when skill dispatched 3+ times and each dispatch re-derives multi-step flows (AGENT.md = subagent briefing, never load into orchestrator context). Same threshold logic applies broadly: **formalize** when ≥3 steps, branching, >5 recurrences, or ≥3 side effects; below that, ad-hoc chains/dedup-as-state suffice. Exception: organic fan-out with natural source-key dedup and zero stuck instances doesn't warrant formalization even at higher recurrence.
**p-tool-integration-contract-readiness** [merged, extended 2026-07-04] When evaluating new tools/frameworks, gate is the integration contract (headless mode, machine-readable output, observability/cost parity) — not language or architecture. Validate via bounded eval on real task subset before deciding rewrite vs integration; run `--help` and a bounded test before finalizing design, since vendor CLI docs lag implementation. **Write-side gotcha**: write-side CLI utilities (writeDistilled, data-mutation APIs) assume prior DB initialization unlike self-initializing read-only CLIs — script-mode calls need an explicit `initDatabase()` first (task #21085).
**p-release-assessment-consumption-gate** [merged, hardened, extended 2026-07-04] Before assessing an SDK release for breaking changes, validate consumption model first: direct/transitive/vendored/unused. Not in package.json + zero imports = close as no-action. **Version currency gate**: if vendored, compare local HEAD date vs release date — if local ≥4 weeks ahead, confirm changes already committed. **Parallel implementation paths**: verify which implementation your codebase actually uses. **Zero-impact surface = zero-code assessment**: harness-internal/transport-layer changes (e.g., Sonnet 5 system-role delivery mechanism) with no dispatch/config/code-surface changes warrant brief assessment + short report, no deep investigation required.
**p-batch-uniform-error-diagnosis** [2026-05-29, hardened, extended 2x] Batch operations returning uniform error signature indicate service-level issue, not individual failures.
