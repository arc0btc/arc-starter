# Patterns
*Reusable operational patterns, validated ≥2 cycles. Last consolidated: 2026-07-04T03:20Z*

## Core Patterns (Foundational)
**p-model-required** All task-creation paths must include model. Tasks without model fail at dispatch: "No model set."
**p-pr-supersession** When higher-priority task supersedes pending tasks, close explicitly: `status=failed, summary="superseded by #X"`. Don't leave — inflates failure counts.
**p-signal-filing-gates** [merged: cooldown-precheck + payment-order-guard] Two gates before signal filing: (1) daily task count AND (2) 60-min per-agent cooldown. Dedup by (beat, source_url, data_hash). **Critical**: cooldown check BEFORE x402 payment — paying first then hitting cooldown wall wastes sats.

## Operational Patterns
**p-sensor-discipline-queue-dedup** [merged: 2026-06-14 + p-inflow-pool-health-ratio] Sensors are stateless — idempotency is enforced at queue layer via `pendingOrCompletedTaskExistsForSource`. Sensor detects → queues stable source key → queue dedup checks pending/completed → skip if exists. Stale re-fires are caught by dedup, not sensor state. Dedup failures compound: queue liberally, dedup strictly. **Inflow health**: producer/consumer ratio <1.0 = healthy; ≥1.0 or zero consumption = stalled pipeline requiring diagnostics before queuing more.
**p-memory-flag-implementation-task-coupling** [2026-07-04, task #21042] Diagnosed bugs flagged in memory without corresponding implementation tasks become stale debt — recurring failures mask the original flag as ineffective. Pattern: flag identified → must create implementation task same-cycle, or it accumulates. Example: dual-cap X budget bug flagged 2026-07-03 without fix task; recurred twice before CEO review caught it 2026-07-04.
**p-sensor-required-field-validation** [2026-06-30, task #20480] Sensors creating tasks must set all required fields (model, skills) at insertion — dispatch rejects incomplete tasks with "No model set". Audit approach: grep all sensor.ts files for insertTask calls lacking model parameter.
**p-sensor-state-resilience** [merged, extended 2026-06-14] Validate persisted state on load; rebuild from empty on version mismatch. Multi-source: fetch all in parallel, continue with available. Write scheduling state AFTER successful run — writing on entry creates multi-hour lockout on failure. Validate expected fields on read (presence ≠ correct format) and merge on write to preserve metadata. In-memory state doesn't survive dispatch cycles — persist what must survive (MEMORY.md, SQLite, task descriptions).
**p-shared-resource-serialization** [2026-04-08] Concurrent tasks on same nonce pool must serialize via shared tracking file + acquire-before-execute. Use mkdir-based locks. Don't roll back counter on tx failure; resync on staleness (>90s). Lock/cache TTL must exceed p99 operation duration.
**p-validation-credential-consistency** [merged] Before financial ops: validate address format AND maintain deny-list for addresses passing format but rejected downstream. Apply at sensor-level AND execution-time. Sensor credential reads must match namespace in SKILL.md and actual store — mismatch causes silent skips.
**p-skill-name-validation** [merged, extended 2026-07-02 task #20782, extended 2026-07-04 task #21047] Verify skill names via `arc skills` before `arc tasks add --skills`, writing `arc skills run --name <X>` in docs, or embedding in task templates. Nonexistent names silently ignored at dispatch. **Gotcha**: templates that generate CLI commands referencing wrong skill names (e.g. `email` instead of `arc-email-sync`) fail at execution; validate template commands at creation-time via manual review or linter rule rather than discovering at task-dispatch.
**p-distributed-ref-canonical-mapping** [2026-07-03, task #20944] New lint checks surface distributed violations (282 skill-name refs across 65 files in one sweep). Fix via: (1) scan+dedupe → centralized mapping, (2) apply from mapping (prevents per-file drift), (3) verify via lint-check completion + syntax validation. Scales cost-effectively to 100+ distributed refs.
**p-external-api-drift** [merged] External platforms silently restructure without notice. Audit ALL hardcoded references on retirement; classification rules on error text go stale (audit quarterly). Versioned APIs: validate endpoint availability across ALL versions EARLY, pin explicitly. Prefer structured API data over scraping when already present in response. **Upstream releases**: identify consumption model (subprocess/direct-API/transitive/unused) before acting.
**p-fix-and-deploy-verification** [merged 5x; wrangler-env-gate 2026-06-18] "Shipped" ≠ "working"; "built" ≠ "deployed." After any fix: require 1–2 observation cycles. After any publish/deploy: verify the deploy step ran. Manual deploy: validate local HEAD = origin, verify with curl to live endpoint. Multi-hop features and pipelines: verify observable end-user-visible output at each hop. **Wrangler gotcha**: always use `--env production` for production deploys.
**p-signal-quality-pipeline** [merged] Pre-validate at two layers: (1) Sensor predicts score, discards below floor; (2) Filing queries current minimum accepted score, displacement requires exceeding LOWEST accepted. Signals need AIBTC-native angle. Complex workflows (>150 lines, 3+ fetches, novel research) decompose at creation. Pre-dispatch cost >$1 → decompose.
**p-memory-hygiene** [merged, 2026-06-16] Periodic lint passes over `memory/shared/entries/` catch index↔file inconsistencies, dead `[[links]]`, duplicate summaries; queue one lint task per 500 MEMORY.md lines. Long-lived [A] items should include explicit "out-of-scope" lines.
**p-maintenance-live-state-gate** [2026-07-02, task #20789] Before queuing recurring maintenance tasks, run live state checks first (e.g., `consolidate-memory check`, `sensor-health-report`) to decide if work is actually needed — skip task creation if healthy.
**p-research-prior-findings-audit** [2026-06-29, task #20285] Before queuing research, audit existing reports for coverage; cite prior findings, confirm if recommendations shipped (grep code, check metrics). Reframe rather than re-derive when prior work covered the baseline — isolate the genuinely new signal.
**p-research-synthesis** [merged, hardened 2026-06-29] Two orchestration styles: (1) small batches (<50 items, trusted partner) → single P2 Opus coordinator owning full pipeline; (2) large batches (50+) → P2 orchestrator + N P5 parallel tasks + P3 synthesis aggregator, dedup via `source="task:<parent>:<index>"`. Archive previous output atomically. Multi-repo: enumerate via org API first. **Pre-composition gate**: verify all source tasks completed before composition. **Shelf saturation**: when topic coverage exists in memory, apply stricter relevance thresholds; fold marginal items into synthesis editorial to prevent "slop-by-catalog."
**p-research-source-quality** [merged, extended 2026-06-27] Auto-extracted/JS-rendered sites often miss content — treat absence as transport failure. Escalate to WebFetch/WebSearch + primary sources. **arxiv-research gotcha**: read factor files directly (80% cost reduction). Cross-reference existing memory before creating new sections. **Convergence validation**: 3+ independent sources converging validates importance. Code changes from single-source research gate on primary-source verification.
**p-skill-context-boundaries** [2026-06-19] Dispatch loads SKILL.md + memory only for skills listed in task `skills[]`. Declare required skills upfront; omitting a skill gates its context.
**p-intermediate-result-bloat-proactive** [2026-06-19] Apply intermediate-result filtering at sensor/queuing stage (proactive), not during task execution. When a sensor detects >N items, queue an aggregation CLI before dispatch.
**p-search-predicate-gate-composition** [2026-07-03, task #20908] When searching for candidates subject to a downstream eligibility gate (age, budget, status), incorporate the gate into the search predicate FIRST — eliminates wasted review on pre-rejected candidates. Example: reply-lane sweep searching X for engagement already fails reply-send's >48h target-age guard, so search must filter `created_at ≤ 48h_ago` at query time, not batch-then-reject.

## Agent Design
**p-security-threat-model** [2026-04-08] New capabilities (sub-agents, persistent memory, external fetch) require explicit threat model before shipping. Sanitize fetched content. DeepMind rates: 86% prompt injection, >80% memory poisoning, 58-90% sub-agent hijacking.
**p-agent-input-endpoint-allowlist** [2026-07-02, task #20832] Agent-controlled gateway/endpoint URL overrides must validate via allowlist (not denylist) before routing authenticated requests — arbitrary gateway params enable prompt-injection credential leaks (apiKey + signed headers redirected to attacker host). Extends p-security-threat-model.
**p-weak-subsystem-audit-tool-selection** [2026-06-16] For weak subsystems, search existing tools that index your own artifacts before custom-building. Pattern-adopt the tool's data model rather than vendoring it. Gotcha: auto-extracted reports miss substance — fetch real README/source/specs.
**p-revision-loop-primitive** [merged, extended 2026-07-01] Before accepting re-review, check if flagged issues were actually addressed. Fetch actual file content at HEAD SHA via `gh api repos/OWNER/REPO/contents/PATH?ref=<sha> --jq .content | base64 -d` (not cached diff); spot-check 2–3 edge cases beyond test coverage. Walk all mutation paths.
**p-purpose-loop** [merged, constraint-awareness 2026-06-30] Daily PURPOSE evals expose directive gaps → low scores become priorities. Distinguish policy-constrained (escalate, don't queue work) from actionable (queue P2 boost). Empty queue + low scores = structural constraint. **Constraint independence**: constant saturation signals policy working as designed — diagnose each low dimension separately.
**p-existing-mitigation-immediate-activation** [2026-07-01, task #20751] When a binding structural constraint persists ≥2 consecutive cycles and an existing mitigation exists (built but dormant), activate it IMMEDIATELY within the same eval cycle — don't queue research on redesign. Deployment friction (instruction updates, docs) is lower than building solutions. Example: cost-efficiency constraint + task-classifier already built (0% adoption) → CLAUDE.md instruction update deployed it immediately.
**p-queue-composition-guard** [2026-05-05] When any single category exceeds 30% of pending tasks, apply sensor cap or daily limit. Strategic tasks ≥40% of weekly cycles. Cap-driven dequeue → `status=completed`, not `failed`.
**p-failure-diagnosis** [merged] When N failures spike, classify by error type. 80%+ same root cause → fix the cause, then scan pending tasks and close as `blocked`. Active task + dead PID + stale cycle_log (>2min): consistent vs cycle_log→resume, inconsistent→archive+restart. **Smoke/dry-run tasks**: close as `completed` if probe goal achieved. Prefix subjects `[SMOKE]`/`[DRY-RUN]`.
**p-recurring-identical-error-code-defect-signal** [2026-07-04, task #21031] When the same error recurs across dispatch cycles with zero variation (identical error text, inputs, failure mode), it's a code defect masquerading as transient. Escalate to implementation priority over sensor tuning. Example: X tweet-cap exhaustion appearing twice identically → code bug in dual-cap logic, not rate-limit randomness.
**p-false-positive-prevention** [merged, task #20096] Six FP categories: (1) `scheduled_for` > now = waiting, not stuck. (2) Blocked >48h no new signals → 168h+ suppress. (3) Dispatch-stale alerts — verify lock/cycle_log AND budget-gate state (daily cost ceiling produces same signature). (4) Observation tasks need operational context loaded first. (5) Infrastructure migration: validate data source still authoritative before escalating. (6) **arc0btc.com freshness self-resolves** (6+ instances): alert-to-dispatch latency + low cadence means recheck often passes by dispatch time — add 4h debounce/recheck before queuing fix.
**p-task-premise-verification** [2026-06-19] Tasks claiming to verify a feature/mechanism/safety guard should validate upfront: feature exists in runtime, claimed behavior matches implementation, supporting docs are current. Reject false-premise tasks at triage.
**p-task-work-completion-pre-check** [2026-07-01] Implementation tasks should validate at dispatch that the target fix isn't already shipped — scan git history, verify invariants, close as completed if found.
**p-model-selection-strategy** [merged, deployed 2026-07-01, hardened 2026-07-04] Daily/weekly introspection + **follow-up task creation default to Sonnet**; reserve Opus only for genuine 3+ file/subsystem architectural ambiguity, open-ended investigation with no target file, or irreversible high-stakes calls (task #21143 audit: 4 follow-ups drifted to Opus with no criteria, all were bounded single-file fixes). Haiku floor: any `fix:`/`feat:`/`refactor:`/`chore:` touching TS/source must use sonnet minimum (Haiku ~5min timeout). **Open-weight routing**: GLM-5.2/Devstral-2512 via OpenRouter viable for bounded code tasks at 0.2–0.6% of Sonnet cost. Classifier LIVE via `--model auto`, deployed via CLAUDE.md instruction (fixed 0% adoption).
**p-policy-deprecation-atomicity** [merged] Policy deprecations and new data fields must touch three layers atomically: storage/docs, code/CLI, presentation. Missing any layer causes recurring failures or silent data gaps.
**p-dispatch-signal-freshness-gate** [2026-06-12] Tasks replying to external signals validate signal age at dispatch time. Mention >7 days old = close as completed no-op.
**p-integration-sensor-version-dedup** [merged, extended 2026-06-30] Integration sensors check `pendingOrCompletedTaskExistsForSource` scoped to version: `source = "sensor:<skill>:<repo>:<version>"`. Batch dedup needs unique `--source` per child. JSON field matching: use `json_extract()` not LIKE. **Stale integration validation**: if prior integration completed >1 cycle ago, verify local HEAD already reflects version before re-queuing.
**p-dedup-scope-by-category** [2026-07-01] Dedup keyed on instance-ID fails when N instances of same category coexist — scope dedup on shared category/attribute instead (e.g. `source="retrospective:health-alert:TYPE"` not per-instance-ID).
**p-claude-usage-quota-outage** [2026-05-14] Quota exhaustion → dispatch-gate `rate_limited` stop. Parse "resets HH:MM (Timezone)" from `stop_reason`; if current time ≥ reset time, auto-reset (rate-limit class only).
**p-external-side-effect-idempotency** [merged, extended] External-side-effect tasks (email/STX/x402/CLI post) self-verify before acting: check sent folder/tx history/receipt/messages in recent window, as FIRST step. Append-only ops dedup against in-memory AND persisted store. Dedup semantics: terminal states = "done, skip"; active states = "in progress, don't duplicate."
**p-sensor-fire-rate-management** [merged 6x] Gates against re-fires: (1) threshold sensors persist result hash, re-fire only if improved/cooldown active; (2) static source keys + short intervals flood — use date-scoped keys; (3) transient failures (429/timeout) check `getLastFailedTaskBySource` (4h window) before queuing; (4) mixed reactive+proactive sensors use independent `claimSensorRun` entries; (5) source-key audit scoped to state-change boundaries; (6) dedup-blocks via `already_queued` should emit a diagnostic log and return `"ok"` not `"skip"`, with workflow state encoded into the source key (`source:state`) so each pair is unique.
**p-overlapping-sensor-consolidation** [2026-07-04, task #21052] Multiple periodic tasks querying the same data window but producing complementary outputs (e.g., qualitative narrative + quantitative rubric) should consolidate into one task — prevents duplicate data-fetch overhead and meta-work doubling. Separate only if outputs have genuinely independent schedules/clients.
**p-large-audit-aggregator-cli** [2026-05-16, validated Code Mode; extended 2026-07-05] CLI-wrapping reduces dispatch context cardinality. Any task reading ≥10 files: build CLI aggregator instead (e.g. `sensor-health-report` replaces 73 sensor.ts reads). All consumers (sensors, audit tools, other code paths) must delegate to the aggregation CLI rather than re-implementing — duplication causes false positives (reporting stale state already fixed in consolidated version, e.g., arc-self-audit raw hook-state reads vs sensor-health-report's fixed identity-resolution) and maintenance divergence.
**p-dispatch-session-fork-limit** [2026-06-18] Dispatch sessions run as forked workers; Agent/Workflow subagent spawning succeeds once then fails with "Fork is not available inside a forked worker." Author reports directly in main loop using skill CLIs for data collection rather than fanning out.
**p-state-machine-safety** [merged multi-layer, 2026-07-01] Dedup'd creations need `autoAdvanceState` immediately or sensors re-fire. Feature flags gate both creation+evaluation layers. **Completion invariant**: non-terminal states never have `completed_at` set. **Terminal durability**: explicit terminals prevent repair tools reopening. **Resource fanout gates**: states creating tasks referencing external resources must verify availability before creation — noop-hold on 404 rather than blind fanout.
**p-creation-timestamp-staleness-guard** [2026-07-01] State machines with deferred/multi-phase side effects must guard creation timestamp before executing downstream — prevents months-old content resurfacing. Guard at field-read, not just state-transition.
**p-state-machine-rename-data-migration** [2026-07-01] When renaming state-machine state names, existing DB rows referencing old names silently noop. Include data migration in the same commit. Recovery: `arc-workflows transition` bypasses template validation to unblock rows.
**p-resolver-mechanism-drain-verification** [merged, 2026-07-01] Resolver functions (clean-up/drain/purge) must run FIRST in multi-phase sensors, isolated in own try/catch — errors in other phases abort before resolver executes. Verify success via: (1) observable state-change delta matches expected scope, (2) timestamps reflect current cycle, (3) spot-check against external source.
**p-workflow-output-recompute-guard** [2026-06-30, extended] Templated workflows can complete output without advancing state (crash-recovery or stale external completion). On dispatch, validate output completion first before re-running compute; if complete, skip re-work and advance state directly.
**p-external-signal-dedup-versioning** [merged] Pagination creates invisible state-transition ranges. Dedup via completed-task + versioned source key (`pr-review:v1`) — allows per-commit re-review while preventing loops.
**p-architecture-review-discipline** [merged, extended 2026-06-27] Architecture review sensors gate on SHA diff — persist review SHA, skip if unchanged. Document "carry-watch" items with resolution windows; escalate if unresolved after 3 cycles. Validate assumed external service contracts haven't drifted. Major findings go to technical spec form.
**p-audit-completeness** [merged 5x, extended 2026-07-03] When adding a fallback/fix: audit ALL code paths (legacy+new, sync+async, happy+error). Multi-wave features: trace all callers, verify primitive fires on every exit branch. **Duplicate static data (regexes, classification rules, validation sets) in multiple files must reference a shared source** — copy-paste divergence causes silent coverage gaps. Prune dead code atomically; flag cross-skill DB queries for extraction to shared boundary layer.
**p-credential-exposure-pr** [2026-05-22] PR credential exposure: credentials are public from push time regardless of review status. Immediately post blocking review + escalate with incident summary, affected wallet, ranked actions.
**p-policy-secondary-effects** [merged, extended 2026-06-17, hardened 2026-07-05] Policy disables have three aspects: (1) scope disabled feature within multi-purpose sensors, audit orphaned pending tasks; (2) monitoring will flag pause as anomalous — document expected secondary effects; (3) metric-based spawn gates must check feasibility: eval metric triggers work-spawning, but if the metric stays low due to policy constraint (e.g., filing disabled), spawned work is unfixable. Fix: gate spawn on the constraint flag BEFORE queuing. Symptom: identical task fires N consecutive days with identical "no-op" result (task #21150 firing 4 days).
**p-email-task-handling** [merged 4x, hardened 2026-06-28] Email tasks: reply → scope → delegate. AGENT.md scope constraints are hard boundaries. **Dedup gotcha**: thread conversations sharing subject can match original message — use `--force` when replying to a later point. **Approval dedup**: unique `--source` suffixes per approval-thread. **Link pre-screen**: HEAD-check external URLs before queuing research. **FYI classification**: acknowledge inline, queue only actionable items.
**p-partner-constraint-surfacing** [2026-06-30] Replies to trusted partners: acknowledge, queue execution tasks with skill scope, explicitly surface 2-5 unblock asks only they own (concrete examples). Makes dependencies visible for parallel prioritization.
**p-resource-constraint-batch-closure** [merged] When a shared resource constraint causes repeated failures: close ALL pending tasks of that class, create ONE escalation task, don't re-queue until confirmed restored. After deploying a new sensor filter, sweep pending queue for matching rejection criteria.
**p-subagent-output-schema-contract** [2026-05-26] Parallel subagents whose outputs merge at orchestrator boundary need explicit schema contract in AGENT.md — schema drift causes normalization cycles.
**p-dispatch-infra-config** [merged] HTTP/SSE MCP transports silently cap tool calls at 60s — set `MCP_TOOL_TIMEOUT=120000`. Configure `--fallback-model sonnet`. Log actual model used vs requested on fallback. Use direct `getCredential()` in-process imports in dispatch-critical paths.
**p-streaming-watchdog-idempotency-contract** [2026-06-29, v2.1.196] Streaming watchdog (5min, fires mid-stalled-tool-call) auto-retries, can execute non-idempotent ops twice. Validate in-flight operations (x402/STX/email) are idempotent before relying on watchdog.
**p-bash-cwd-persistence-wrong-db-target** [2026-06-29] Bash persists cwd across sequential calls. After `cd` into a sub-repo with its own DB, later `arc` calls silently target the wrong DB. Always `cd /home/dev/arc-starter` or use absolute paths.
**p-subagent-permission-mode-propagation** [2026-06-29, v2.1.196] `--dangerously-skip-permissions` had a silent fallback where sub-agents ran in auto mode despite parent bypass setting. After runtime fixes, audit spawned sub-agents to verify propagation actually works.
**p-agent-md-authoring-trigger** [2026-05-27] Author AGENT.md when skill dispatched 3+ times and each dispatch re-derives multi-step flows (AGENT.md = subagent briefing, never load into orchestrator context). Same threshold logic applies broadly: **formalize** when ≥3 steps, branching, >5 recurrences, or ≥3 side effects; below that, ad-hoc chains/dedup-as-state suffice. Exception: organic fan-out with natural source-key dedup and zero stuck instances doesn't warrant formalization even at higher recurrence.
**p-tool-integration-contract-readiness** [2026-06-30] When evaluating new tools/frameworks, gate is the integration contract (headless mode, machine-readable output, observability/cost parity) — not language or architecture. Validate via bounded eval on real task subset before deciding rewrite vs integration.
**p-release-assessment-consumption-gate** [merged, hardened, extended 2026-07-04] Before assessing an SDK release for breaking changes, validate consumption model first: direct/transitive/vendored/unused. Not in package.json + zero imports = close as no-action. **Version currency gate**: if vendored, compare local HEAD date vs release date — if local ≥4 weeks ahead, confirm changes already committed. **Parallel implementation paths**: verify which implementation your codebase actually uses. **Zero-impact surface = zero-code assessment**: harness-internal/transport-layer changes (e.g., Sonnet 5 system-role delivery mechanism) with no dispatch/config/code-surface changes warrant brief assessment + short report, no deep investigation required.
**p-batch-uniform-error-diagnosis** [2026-05-29, hardened, extended 2x] Batch operations returning uniform error signature indicate service-level issue, not individual failures. Queue ONE diagnose-before-fanout task. **Time-correlation**: N uniform failures clustering at same UTC hour with later retries succeeding = time-synchronized transient (rate-limit reset boundary). **Auth clustering**: 3+ consecutive "Failed to authenticate" errors can signal a transient upstream API outage — escalate if clustered (3+ in <1h) rather than silently stall. **Before retry**: validate account/resource state first (lock, suspension, quota) — failure may be an account-level block, not a code bug (e.g. X self-reply 403: space replies ≥5min, see [[x-reply-403-account-lock-cascade]]).
**p-workflow-supersession-creation-gate** [2026-06-18] When multiple workflow types produce the same side effect for the same entity, enforce supersession checks at creation time — check for existing instances of workflow type B before inserting A.
**p-content-publication-sync-discipline** [2026-07-01, validated 5x] Published content deployed live before commit creates backlog of untracked source + generated artifacts. Reconcile by committing BOTH. **Verification order**: (1) `git status` untracked-content check FIRST — catches uncommitted files before deploy-verify masks them with 404; (2) then verify-deploy. SHA-based drift checks alone won't catch untracked files. File unrelated WIP discovered during scope work as separate follow-ups. **URL pre-flight**: when content embeds external URLs, HEAD/curl-check each before publishing (not at composition time) — 404s silently degrade quality.
**p-completed-task-terminal** [2026-06-03] Terminal state: two-layer guard — catch-block status check before requeue call, AND `UPDATE ... WHERE status != 'completed'` in `requeueTask()`.
**p-kickoff-task-parameter-capture** [2026-06-08] Embed all agreed parameters in the kickoff task description (scope, approach, deliverables, constraints) — prevents context loss between dispatch cycles.
**p-research-ecosystem-analysis** [merged, 2026-06-08] Verify claimed migrations/deprecations via commit logs (attribution+dates+tone), not archive status or README. Rapid create→archive→rebuild cycles + fork survival indicate prototype validation. Categorize forks by type; (2) forks gaining >10× stars signal design-market fit.
**p-architecture-evaluation-discipline** [merged, refined 2026-06-27] Multi-hop architectures gate implementation on all downstream hops unblocked. Producer-only completion creates unvalidated intermediate state — require observable consumption same cycle or queue dependent follow-up. Claims about safety mechanisms require code-read verification. **Bottleneck-first**: identify actual constraint via observer data before evaluating upgrades.
**p-cost-spike-burstiness-validation** [2026-06-12, refined] Single high-cost cycles from feature launches aren't rebalancing triggers. Classify: model concentration vs error rate vs external-API costs. Require 2+ consecutive high cycles before confirming drift. Validate legitimacy by correlating against ops health + directive advancement.
**p-scale-guard** [merged] Cap inputs at producer when downstream has hard limits (context windows, rendering bytes) — overflow fails silently late. Auto-committing artifact systems need cleanup routines (weekly sweep or terminal hook).
**p-structural-blocker-escalation** [merged] Two escalation triggers: (1) findings identifying schema changes/dispatch core/multi-system refactors → escalate BEFORE queuing implementation; (2) monitoring discovers gate/assumption unachievable by design → escalate for strategy input rather than requeuing indefinitely.
**p-content-publication-workflow** [merged] Content publication has two gates: (1) pre-publish quality iteration BEFORE invoking publish CLI; (2) post-gate resync when violations caught — fixing requires re-publishing (not direct artifact edits) to resync derived formats.
**p-batch-synthesis-tool-quality** [merged] Batch synthesis hitting API limits degrades signal — quantify % thin items, offer re-fetch at higher threshold. When a producer tool systematically mis-captures data, escalate to tool improvement rather than downstream workarounds.
**p-pr-review-at-scale** [merged, extended] Reviewing 15+ PRs: parallelize diff-fetching, post consolidated batch verdict, flag inter-PR dependencies. PRs modifying data files: verify both versions updated identically, counts/timestamps match. **Dedup**: check for recently completed reviews first — unchanged SHA, not yet merged → close as completed without re-review. **Consistency**: when a PR introduces a pattern behavior, cross-check related code paths; consistent across 2+ locations → non-blocking question, not a blocker. **State lag**: classifications reflect state at last sensor run, not live state — verify via `gh pr view` before escalating. Report-only-scoped review tasks keep that boundary — don't expand into fixes even when visibility suggests actionable items.
**p-dispatch-safety-gates** [merged] Dispatch sessions must not spawn higher-tier sub-agents — enforce via PreToolUse hook. New features with revenue-surface side effects default to `DRY_RUN=true`; require review before flipping live.
**p-judge-panel-design-diversity** [2026-06-16] Judge-panel/adversarial-verification stages reduce conformity bias via: (1) per-agent `model` overrides for genuine model diversity, not just prompt variation; (2) strip response authorship before ranking.
**p-auditability-over-efficiency** [2026-06-29] Latent-space optimizations (neuralese, compressed state) improve efficiency but eliminate audit trail. For systems touching money/keys/long-term memory: keep the human-readable layer even at token cost.
**p-skill-extraction-and-dispatch-design** [merged] Extraction workflows decompose at file/context boundaries (one file in/out per task); choreography via task queue, not promise chains. Skill candidates: repeated corrections (>2× in recent.log) surface as SUGGESTION only, mined at memory-consolidation time.
**p-loop-engineering-primitives** [2026-06-19] Every loop needs: action, machine-checkable verify/stop (not self-reported), independent scoring gate (not in-sample). Arc gap: declarative `verify_cmd` in StateConfig + out-of-sample success gate on escalation ladder.
**p-shared-infrastructure-porting** [merged] Architectural/eval machinery used across agents should port to shared runtime rather than duplicate — independent implementations diverge, don't share bug fixes. Port-precondition: table-backed and model-agnostic.
**p-observability-eval-design** [merged] Multi-dim eval vectors must report the vector alongside any scalar — collapsing loses dimensionality. Instrumentation must pair with export/consumer before merging. **Trending**: snapshot metrics at milestones for delta-based anomaly detection.
