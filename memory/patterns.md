## Core Patterns (Foundational)
**p-task-closure-discipline** [merged: p-pr-supersession + p-workflow-supersession-creation-gate 2026-06-18 + p-review-task-confirmed-resolution-closure 2026-07-05 task #21309 + p-terminal-task-state-immutability 2026-07-11 task #22005/#22006 + p-claimed-side-effect-verification 2026-07-20 task #23255] Four task-closure rules: (1) **supersession** — when a higher-priority task/workflow supersedes pending work, close it explicitly (`status=failed, summary="superseded by #X"`) rather than leaving it to fail on its own — inflates failure counts and confuses audit trails; for workflow types producing the same side effect for the same entity, enforce the check at creation time too (verify no existing instance of workflow type B before inserting A); (2) **confirmed-resolution** — when a review/monitoring task confirms an external condition is resolved (blocked PR merged, bug fixed, workflow unblocked), take terminal action (close the blocked task) in the same cycle, not just report the finding — otherwise the condition re-triggers at full cost next sensor cycle (e.g. PR #638 blocked-task reviewed 3× same day before this was enforced); (3) **terminal immutability** — completed/failed/blocked states must guard against re-closure, since unconditional re-close resets `completed_at` and pulls stale tasks back into time-windowed retrospective lookback, creating infinite loops (task #21072/#20899); guard at CLI layer (`cmdTasksClose` rejects re-closure on terminal tasks with exit 1); (4) **claimed-side-effect verification** — when closing a task with a summary claiming it performed a side effect (CLI invocation, state transition, external action), verify the action actually executed BEFORE closing, not as narrative in the summary — writing "transitioning to no_action" is not the same as invoking the CLI; task #23255 found three workflow-assess tasks closed with summaries claiming transitions that never occurred, leaving workflows stuck in intermediate states; discovery requires verification against final observable state.
## Operational Patterns
**p-distributed-system-audit-visibility** [2026-07-17, task #23050] When distributed systems (agent dispatch + external control plane) share state, control-plane mutations (git revert, snapshot restore) are invisible in local cycle_log/git history. Reversions wiping operational state markers (email-send confirmation flags, deployment markers) create irrecoverable investigation dead-ends. Mitigation: require explicit reason fields in all cross-repo mutations (commit body, structured logs) and maintain shared audit trails linking local decisions to external changes.
**p-exemption-list-saturation-detector-evolution** [2026-07-19, task #23153] When a detector/validator accumulates exemptions or manual overrides at predictable cadence (≥1 per review cycle × 3+ consecutive), the underlying rule is incomplete — generalize the detector instead of adding more exemptions. Exemption-list data reveals what the detector should learn: broad categorization rules (common prefix variants, state-pattern classes) instead of enumerating instances. Cost: one rule redesign (~10–20 lines) vs indefinite exemption-list maintenance. Example: six narrow exemptions over six cycles → extract the common pattern (retrospective-chain trigger-source family) and teach the detector natively, resetting the exemption list. Signal-to-action: after ≥3 cycles same-cadence growth, create ONE generalization task instead of continuing exemption-stack accumulation.
**p-sensor-discipline-queue-dedup** [merged: 2026-06-14 + p-inflow-pool-health-ratio + p-sensor-required-field-validation 2026-06-30 task #20480] Sensors are stateless — idempotency is enforced at queue layer via `pendingOrCompletedTaskExistsForSource`. Sensor detects → queues stable source key → queue dedup checks pending/completed → skip if exists. Stale re-fires are caught by dedup, not sensor state. Dedup failures compound: queue liberally, dedup strictly. Sensors creating tasks must also set all required fields (model, skills) at insertion — dispatch rejects incomplete tasks with "No model set" (audit via grep for `insertTask` calls lacking a model param). **Inflow health**: producer/consumer ratio <1.0 = healthy; ≥1.0 or zero consumption = stalled pipeline requiring diagnostics before queuing more.
**p-sensor-state-resilience** [merged, extended 2026-06-14] Validate persisted state on load; rebuild from empty on version mismatch. Multi-source: fetch all in parallel, continue with available. Write scheduling state AFTER successful run — writing on entry creates multi-hour lockout on failure. Validate expected fields on read (presence ≠ correct format) and merge on write to preserve metadata. In-memory state doesn't survive dispatch cycles — persist what must survive (MEMORY.md, SQLite, task descriptions).
**p-shared-resource-serialization** [2026-04-08] Concurrent tasks on same nonce pool must serialize via shared tracking file + acquire-before-execute. Use mkdir-based locks. Don't roll back counter on tx failure; resync on staleness (>90s). Lock/cache TTL must exceed p99 operation duration.
**p-validation-credential-consistency** [merged] Before financial ops: validate address format AND maintain deny-list for addresses passing format but rejected downstream. Apply at sensor-level AND execution-time. Sensor credential reads must match namespace in SKILL.md and actual store — mismatch causes silent skips.
**p-skill-name-validation** [merged, extended 2026-07-02/07-04/07-07] Verify skill names via `arc skills` before `arc tasks add --skills`, writing `arc skills run --name <X>` in docs, or embedding in task templates — nonexistent names are silently ignored at dispatch. **Gotcha**: templates generating CLI commands with wrong skill names (e.g. `email` instead of `arc-email-sync`) fail at execution; validate template commands at creation-time (manual review or linter), not at dispatch. **Distributed-caller audit**: when a skill is renamed, grep-audit all spawning paths (`grep -r "old-name" skills/ src/`) — multiple unrelated generators often reference the same name independently, so fix all spawning points atomically rather than partially. At scale (100+ refs across many files): scan+dedupe into a centralized mapping, apply from the mapping to prevent per-file drift, verify via lint-check + syntax validation.
**p-external-api-drift** [merged, extended 2026-07-08 tasks #21712/#21744, extended 2026-07-09 task #21874, extended 2026-07-16 task #22964] External platforms silently restructure without notice — audit ALL hardcoded references on retirement, and audit error-text classification rules quarterly since they go stale. Versioned APIs: validate endpoint availability across ALL versions EARLY, pin explicitly. Prefer structured API data over scraping when already present in response. **Upstream releases**: identify consumption model (subprocess/direct-API/transitive/unused) before acting. **Mechanism validation**: before investigating issues on external platforms, confirm the claimed mechanism/feature still exists (live docs, changelog, support history) — feature retirements/policy deprecations invalidate investigation premises mid-work (e.g. classified-payment issue #480 was obsolete because automated-payout had already been deprecated). **Field-limit discovery**: undocumented field-length limits (e.g. Whop's 1500-char product descriptions, 80-char title/headline) cause redundant fix cycles when found at execution time — validate boundary-value payloads at skill-integration time and document constraint bounds in SKILL.md. **Free-field optimization** [merged: p-api-free-field-optimization, 2026-07-14 #22656]: APIs billing per-request often support unlimited fields at no marginal cost — request all available fields upfront (X's `tweet_fields` doesn't add cost; full field set eliminated 125/195 bare-t.co declines via URL extraction). **Identifier-collision escape** [merged: p-auto-generated-external-identifier-collision-escape, 2026-07-06 #21425, validated 2026-07-19 task #23139/#23219]: platforms with global-namespace auto-derived identifiers (Whop routes, handles) only reveal collisions at claim-time — expose CLI flags for post-discovery correction rather than DB surgery. Generic slug derivation (e.g., "research" from report filename lacking descriptive suffix) commonly triggers collisions; document fallback slug derivation logic and ensure --route flag enables post-discovery patching. **Ecosystem verification** [merged: p-research-ecosystem-analysis, 2026-06-08]: verify claimed migrations/deprecations via commit logs (attribution+dates+tone), not archive status; rapid create→archive→rebuild + fork survival indicates prototype validation, forks gaining >10× stars signal design-market fit. **Passive-hardening watch** [merged: p-upstream-passive-hardening-monitoring, 2026-07-02/06-29]: monitor upstream runtime releases for trust-boundary/transport-layer fixes that passively harden existing patterns with zero code changes (watch for "Fixed subagent X" / "Fixed parent agent receiving Y" in release notes); when a foundational dep ships a fix affecting a multi-layer call stack, audit that it actually propagated through ALL layers — a fix on one layer doesn't auto-propagate to callers. **Conditional field omission** [2026-07-16, task #22964]: APIs that conditionally omit keys based on field truthiness (e.g., `...( flagged ? { flagged, flagReason } : {})`) create silent confusion — consumers expecting key presence misinterpret absence as non-existence or unimplemented features. Verify field inclusion logic via code inspection; document conditional-spread semantics explicitly in API/schema docs (e.g., "flagged key omitted when false") to prevent misattribution of missing keys as unimplemented features; when investigating "feature missing" claims, verify via code-read first. **Cumulative cost batching** [2026-07-19, #23168]: APIs with per-query resource budgets that scale with complexity (GraphQL PR/review counts, field counts) fail at the limit as batch size grows — resource-limit errors look transient but mean 'query too big,' not a service hiccup; estimate cost upfront, auto-chunk to a calibrated safe batch size, and validate result counts match expected to catch silent under-batching.
**p-fix-and-deploy-verification** [merged 5x; wrangler-env-gate 2026-06-18] "Shipped" ≠ "working"; "built" ≠ "deployed." After any fix: require 1–2 observation cycles. After any publish/deploy: verify the deploy step ran. Manual deploy: validate local HEAD = origin, verify with curl to live endpoint. Multi-hop features and pipelines: verify observable end-user-visible output at each hop. **Wrangler gotcha**: always use `--env production` for production deploys. **Regeneration idempotency** [merged: p-regeneration-idempotency-deployment-verification, 2026-07-09 #21851]: regeneration tasks verify byte-for-byte output match to HEAD (confirming idempotency) AND validate live deployment independently (catches deploy-drift git-status misses); stage only task-owned files in mixed worktrees. **Build-recovery** [merged: p-subprocess-memory-pressure-build-recovery, 2026-07-13 #22237]: nested build-tool subprocess chains amplify memory pressure under tight VM headroom — a segfaulting build (exit 139) often succeeds run directly outside the CLI wrapper; after manual recovery, re-run the standard deploy CLI to record orchestration state consistently.
**p-early-close-subprocess-idle-timeout-cost-waste** [2026-07-17, task #23050/#23053] When dispatch tasks call `arc tasks close` early and exit before the subprocess completes naturally, the subprocess idles until the hard 500s timeout fires — wasting ~$2.50/task in unused dispatch cost. Mitigation: after `arc tasks close`, immediately exit the session cleanly (return/end-of-script) rather than letting it idle, or structure close-then-continue as separate tasks rather than same-task sequential ops. Cost impact: task #23050 wasted $2.51 in a 500s idle window that should have been a 50s session; cost-scaled: if X% of cycles close early without clean exit, multiply daily cost × X% to quantify waste driver.
**p-immutable-marker-capture-timing** [2026-07-14, task #22476] In multi-step build/deploy pipelines with side-effecting intermediates (commits, sign operations), capture immutable markers (current SHA, deployment ID) AFTER all side-effecting steps complete, not before. Capturing before side-effects leaves the marker stale when intermediate steps create new state (e.g., SIP-018 sign-sweep commits), causing permanent false-alert loops downstream (false drift alerts, stale health checks recurring indefinitely). blog-deploy captured currentSha before the sign-sweep which can commit, leaving deployed SHA stale and triggering recurring drift alerts; fixed by re-reading HEAD after the sweep. Applies to any health check or verification depending on immutable state markers in orchestrated pipelines.
**p-signal-quality-pipeline** [merged] Pre-validate at two layers: (1) Sensor predicts score, discards below floor; (2) Filing queries current minimum accepted score, displacement requires exceeding LOWEST accepted. Signals need AIBTC-native angle. Complex workflows (>150 lines, 3+ fetches, novel research) decompose at creation. Pre-dispatch cost >$1 → decompose.

**p-research-relevance-and-redirect-filters** [merged: p-research-domain-relevance-prefilter + p-research-mainstream-saturation-sku-filter + p-research-infrastructure-gap-redirect + p-classification-restraint-accept-sparse-output, 2026-07-14/15, tasks #22488/#22616/#22617/#22786; extended 2026-07-17 task #23016] Four gates when distilling research into predefined categories: (1) **domain prefilter** — apply keyword/stack-fit pre-filters before composition, skip candidates lacking domain keywords (MCP, x402, bitcoin, stacks) or direct architectural relevance (arXiv screening prioritized agent-architecture findings, skipped VEXAIoT IoT pentesting as stack-tangential); (2) **mainstream-saturation SKU filter** — before flagging research as a paid-SKU candidate, check if mainstream crypto press already covers it well; if so, cite rather than publish (Jeremy Allaire's agentic-economy treatise was already thoroughly covered, eliminating publication incentive); (3) **infrastructure-gap redirect** — when research validates a capability already exists, redirect energy to gaps in adjacent layers (orchestration, workflow gating, integration points) rather than re-confirming the capability (Codex-in-Claude-Code research found the SDK already handles it; real gap was cross-model adversarial-review missing from the PR workflow). **Same-category-different-layer variant** [2026-07-17, task #23016]: when research surfaces an optimization/capability category, cross-check Arc's code for the analogous mechanism; if confirmed but via different deployment model (self-hosted vs. API consumer), evaluate deployability under Arc's current architecture — capability parity without deployment leverage warrants no follow-up. **p-auto-commit-type-regression-blind-spot** [2026-07-15, task #22717/#22721] Fallback auto-commit paths (unattended dispatch cycles committing `memory/`, `skills/`, `src/`) bypass normal per-dispatch session oversight — resulting type-level regressions (wrong arg types, dropped required fields, mismatched JSON/array serialization) ship silently. Pre-commit syntax guard (Bun transpile) catches syntax errors but misses type-level semantic bugs (caller expects `string`, passes `array`; caller requires `model` field, omitted). Post-commit service health check detects dead services but not runtime type errors in sensor/background logic. Consequence: sensors or background jobs throw at runtime on every execution, halting functionality for hours until discovered in architecture review. Mitigation: add a `tsc --noEmit` baseline-drift sensor (30-min cadence) running real type-check on touched files, surfacing error-count increases in auto-committed `.ts` files; flag as advisory follow-up (doesn't block commit since type-errors aren't crashes, but surfaces the regression for same-cycle code review + fix). Distinguish from type-safe compilation gates (require pre-commit passage): type-check-drift is a *post-commit observation tool* for auto-commits specifically, catching the gap between "syntax OK" (passes transpile) and "semantically correct" (passes type-check).
**p-skill-context-boundaries** [2026-06-19] Dispatch loads SKILL.md + memory only for skills listed in task `skills[]`. Declare required skills upfront; omitting a skill gates its context.
**p-task-generator-skill-delegation-context-review-exempt** [merged, extended 2026-07-16, task #22796/22958] Context-review detectors false-flag three patterns: (1) task generators shelling out to downstream skills via CLI (e.g., arc-article-pipeline: `→blog-publishing create`) without needing context; (2) one-off ad-hoc follow-up tasks (source `task:X`, already completed) don't represent systematic gaps; (3) investigation tasks describing multi-domain symptoms/blast-radius (e.g., nonce-tracker affecting zest-supply) mention domains only as scope, not required context. Fix: source/completion-status pre-filter for (2); scope-audit distinguishing symptom-mentions from required-context for (3). Prevents false-positives on self-contained orchestration, completed follow-ups, and investigative tasks.
**p-meta-consolidation-self-timeout** [2026-07-08, tasks #21511/#21531/#21535; validated 2026-07-09 task #21787/#21795] Consolidation tasks operating on Arc's own ever-growing self-referential files (`patterns.md`, `MEMORY.md`) monolithically re-read + rewrite the whole file once it crosses a line threshold — this both timed out at 15min on sonnet tier (#21511, 175 lines) and cost 2 follow-up passes at $2.9+ each (#21531/#21535) to recover. Fix: once a self-referential file exceeds its threshold, decompose the consolidation into per-section subtasks (one per `##` header) with a final merge pass, rather than one task rewriting the entire file — mirrors `p-large-audit-aggregator-cli`'s "decompose reads ≥10 files" rule but applies it to writes/edits on a single large file, not just reads across many files. **Validation** (task #21795): Agent Design section (21 entries, 151 lines) consolidated in one pass by merging 5 synonym pairs (24% overlap density), reduced to 146 lines, no timeout, no syntax issues; confirms per-section granularity is the right unit. **Metric gotcha** (validated #21787): entry-count reduction (merged 5 pairs, cut 21→16 entries) doesn't correlate linearly with file-size reduction (189→185 lines, only 4 lines saved) because parent entries grow in length when absorbing child entries — when metric-driven targets are line-count or char-count, monitor both dimensions during consolidation or merge/prose-tightening may be insufficient; `p-memory-lifecycle` prose-density passes provide secondary compression if entry merging alone misses targets. **Lint cadence** [merged: p-memory-hygiene, 2026-06-16]: periodic lint passes over `memory/shared/entries/` catch index↔file inconsistencies, dead `[[links]]`, duplicate summaries; queue one lint task per 500 MEMORY.md lines. Long-lived [A] items should include explicit "out-of-scope" lines.
**p-search-predicate-gate-composition** [2026-07-03, task #20908; extended 2026-07-08, tasks #20988/#21022/#21024/#21157/#21158/#21162/#21174] When searching for candidates subject to a downstream eligibility gate (age, budget, status), incorporate the gate into the search predicate FIRST — eliminates wasted review on pre-rejected candidates. **p-security-threat-model** [merged, extended 2026-07-02 task #20832; merged 2026-07-08 task #21776; cross-referenced 2026-07-09 against [[deepmind-6attack-taxonomy-ingestion-audit]] task #21474; merged: p-credential-exposure-pr 2026-05-22 + p-subagent-permission-mode-propagation 2026-06-29 v2.1.196] New capabilities (sub-agents, persistent memory, external fetch) require explicit threat model before shipping. Sanitize fetched content. DeepMind rates: 86% prompt injection, >80% memory poisoning, 58-90% sub-agent hijacking. Agent-controlled gateway/endpoint URL overrides must validate via allowlist (not denylist) before routing authenticated requests — arbitrary gateway params enable prompt-injection credential leaks (apiKey + signed headers redirected to attacker host). **Pre-wiring review**: security-adjacent subsystems (injection defense, sanitization, key management) gate deployment on multi-lens review across independent expert perspectives (correctness, edge-cases, attack scenarios, performance, maintainability); AGENT.md must disclose coverage boundaries ("protects X but not Y") rather than overstating scope — converge on pass, divergence flags gaps before wiring to production. The 2026-07-06 DeepMind 6-attack ingestion audit validated this pattern rather than superseding it — its concrete fixes live as their own entries, not duplicated here: `AGENT.md` "data not instructions" framing → [[p-agent-md-authoring-trigger]] untrusted-input override; CSS-hidden-text stripping → `p-css-aware-content-sanitization`; unprovenanced `recent.log`→MEMORY.md poisoning path → `p-consolidation-untrusted-source-gates`. **Credential exposure**: PR credential exposure is public from push time regardless of review status — immediately post blocking review + escalate with incident summary, affected wallet, ranked actions. **Sub-agent permission propagation**: `--dangerously-skip-permissions` had a silent fallback where sub-agents ran in auto mode despite parent bypass setting — after runtime fixes, audit spawned sub-agents to verify propagation actually works.
**p-security-mechanism-ground-truth** [2026-07-17, task #23029] When researching claimed security mechanisms (sandboxing, isolation, approval gates), verify actual runtime state via config inspection + code-path review, not documentation alone. Disabled mechanisms with compensating layers = acceptable; disabled mechanisms with no fallback = exposure. Example: Arc's dispatch has `sandbox.enabled: false` + `bypassPermissions`, so real isolation comes from arc-worktrees + pre/post-commit guards, not the sandbox itself — only ground truth against actual config distinguishes real isolation from false confidence.
**p-guard-coverage-completeness** [2026-07-17, task #23029] Security guards protecting against a threat class must enumerate ALL manifestations, not just named instances. Example: PreToolUse hooks guarding specific file paths (4 sensitive files) but leaving destructive commands globally available (rm -rf, truncate, etc.) is incomplete — threat class is "destructive actions," not just "edits to file X"; guards must span the class or document gaps explicitly for remediation.
**p-type-widening-without-exhaustive-branch-update** [2026-07-20, task #23239; refined cycle-2 validation 2026-07-20, task #23241; extended 2026-07-20, task #23247] When a type union/enum is widened (adding a new discriminant case), downstream code with exhaustive if/else branches written for the prior type set include implicit `else` fallbacks that become stale — the new case falls through to default behavior. On fund-moving/critical code paths, stale branches create real risks (e.g. widening asset-type enum to include USDCx but fund-execution code still only special-casing sBTC creates a fallthrough to incorrect asset-type handling). PR code-path review on payment/fund-moving/security-critical paths must exhaustively trace type-change ripple-effects through all downstream if/else/match branches (grep type name, validate each branch updates); syntax-checking alone is insufficient. **Parallel subsystems caveat** [cycle-2 re-review validation #23241]: new asset types in payment flows often have PARALLEL redundant safety checks (transfer path + balance validation, limit checks + approval gates) — audit all parallel paths together for consistency, not just the primary/immediate handler, since one path lacking the new type-case causes silent fallthrough on the paired check. Re-review discipline: spot-check 2–3 edge cases including parallel subsystems, not just the flagged code path. **Same-file matching-contract consistency** [2026-07-20, task #23247]: when a file has multiple handlers for the same data type (asset, identifier, contract), verify they use identical parsing/matching contracts — divergence causes silent failures when new code uses one contract and existing code uses another (e.g. new `selectPaymentOption()` matching `"sBTC"` via `endsWith(".sbtc")` while existing `detectTokenType()` in same file uses `.sbtc-token` suffix). Discovery: grep file for all handlers of target type, cross-check matching logic; live tests often miss divergence since they exercise only new paths. PR review gate: when adding a new handler for a type handled elsewhere in the file, spot-check matching-logic consistency across all same-file handlers before approval.
**p-denylist-guard-naive-text-match-gotcha** [2026-07-17, task #23031] Text-matching-based deny-list guards (PreToolUse hooks, CLI filters) fire on pattern strings embedded in literal content (heredoc strings, commit-message documentation, config values), not just command invocation. Mitigation: use structured parsing (AST/shell parsing) instead of naive substring matching, or carefully wordsmith embedded documentation to avoid triggering blocked-pattern text. Example: guard documenting itself ("blocks rm -rf, git reset --hard") self-triggered on re-commit.
**p-security-tool-finding-suppression-at-integration** [2026-07-17, task #23045] When security/quality scanners flag findings in auto-generated or infrastructure files (hooks, scaffolding, generated code), filter those findings at your integration layer rather than waiting for upstream config support. Critically: do not trust the tool's exit code if you're post-processing its output — compute decisions (blocked/proceed) based on YOUR suppression-adjusted counts, not the raw tool exit code. Example: AgentShield exit code 2 reflects raw critical count pre-suppression; decision must re-compute critical count AFTER filtering hook files, not blindly trust `exitCode`. False positives in infrastructure code are expected noise — suppress by file pattern at evaluation boundary, not upstream, since upstream config may not exist in your tool version.
**p-revision-loop-primitive** [merged, extended 2026-07-01, extended 2026-07-20 task #23268] Before accepting re-review, check if flagged issues were actually addressed. Fetch actual file content at HEAD SHA via `gh api repos/OWNER/REPO/contents/PATH?ref=<sha> --jq .content | base64 -d` (not cached diff); spot-check 2–3 edge cases beyond test coverage. Walk all mutation paths. **Fallback-code-stale gotcha**: when reviewing bugfixes that refactor primary data-extraction paths (e.g., reading `.value` nesting instead of top level), audit ALL fallback/error-handling branches and error-message logic that reference the old structure — these paths often cache old shape assumptions silently, returning wrong values (0s) or stale text instead of failing loud. Code-path review must trace not just happy path but exception handlers, type guards, and error fallbacks.
