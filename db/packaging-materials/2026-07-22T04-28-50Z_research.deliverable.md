## Key Takeaways

### @jainarvind (Arvind Jain, CEO Glean) — HIGH — "Enterprise AI economics is an architecture problem"
X longform article (404k impressions, 219 likes). Cited claims, verbatim from the piece:
- **"The price of a token keeps falling, and enterprise AI bills keep rising."** A request fans out into retrieval + tool calls + reasoning loops + multi-step execution, so tokens/task climb faster than price/token drops. Cites Chamath (All-In) on token costs "doubling every 45 days" vs a "5%, max" productivity lift, and Palo Alto CEO Nikesh Arora (CNBC): AI pricing must fall ~90% to be broadly useful.
- **"Stop measuring cost per token and start measuring cost per successful task. A cheap model that produces rework is expensive."** The engineering discipline is deciding *where expensive intelligence earns its price*.
- **Real model choice as a governed layer:** DoorDash reserves a frontier model for hardest code-review, routes lower tasks to cheaper; Decagon reportedly sends ~90% of mature support to open models. Glean's Model Hub = 30+ commercial + open models behind one access-controlled/audited layer, "model layer can change underneath you without forcing a rebuild."
- **Open models are no longer the weak option:** "GLM-5.2 has landed within about a point of the best closed models on long-horizon coding while running at roughly a sixth of the cost, and Kimi K3 arrived as the largest open-weight model yet, debuting at number one on a leading coding benchmark ahead of the best systems from Anthropic and OpenAI." (Sourced to venturebeat.com/.../glm-5-2-beats-gpt-5-5.)
- **Token efficiency > token count:** Glean's "Waldo" agentic-search model (built on open NVIDIA Nemotron) plans the search ahead of the frontier model, cutting token use ~25% and latency ~half at equal quality. Context-layer swap benchmark (Claude Cowork): Glean index preferred ~2.5x as often, off-the-shelf MCP used ~30% more tokens; win rate rose 66%→73% as tasks got harder.
- **Moat thesis:** "The models will keep leapfrogging each other. The architecture around them is what becomes the moat."

### @poolsideai (Poolside) — MEDIUM — Laguna S 2.1 release
530k impressions. 118B total-param MoE, 8B activated/token, up to 1M context, thinking/no-thinking modes. "Capable enough to hold its own against models many times its size. Small enough to run on a single @NVIDIAAI DGX Spark." **Fully open under OpenMDW-1.1, weights on HuggingFace today.** Concrete evidence for the "own (run locally) vs rent" axis of the thesis — a frontier-aspirant coding model you can self-host.

### @jack (Jack Dorsey) — LOW — Buzz launch
"a new groupchat platform for teams of people and agents… model-agnostic, decentralized, self-sovereign, and open source." Reduces dependency on Slack/GitHub. Thesis-adjacent (open + self-sovereign agent infra) but early-stage, no numbers, no Arc code hook. Noted, not actionable.

## Arc-Alignment

**Direct code hook (verified this cycle):** `src/classifier.ts` is a working implementation of Jain's central argument. Its header comment states the goal outright — route by task type to the cheapest sufficient model:
- `bounded-code → openrouter:devstral (~$0.003/task)`, `bounded-code-glm → openrouter:glm (~$0.01/task)`, `operational → haiku`, and only `infrastructure → opus`.
- This is "cost per successful task, route the work, reserve frontier for the hard step" in code. The policy rationale lives in `memory/shared/entries/openrouter-open-weight-routing.md`; the CLI surface is `arc tasks add --model auto` (CLAUDE.md documents it for bounded single-file follow-ups).

**Live signal for Arc's own routing table:** The GLM-5.2 / Kimi K3 benchmark movement is the strongest external validation to date that Arc's `openrouter:glm` tier is correctly placed — and a prompt to check whether the classifier's GLM tier should widen (currently gated to bounded code). Laguna S 2.1 (open, single-DGX-runnable) is a candidate to watch if Arc ever adds a self-hosted coding tier, though that's well beyond current infra.

**No hand-wave:** the "moat is the architecture around the models" line is directly what Arc's dispatch + classifier + escalation-ladder stack *is* — the durable layer, model-agnostic underneath. This report does not propose a code change; it confirms the existing bet is well-aligned with a credible primary source and files the benchmark cites as forward-looking justification.
